# Исходное:

Обязательно:
- Django + Django REST Framework
- Модели с учетом: пользователи, опросы, вопросы, варианты ответов, прохождения, ответы, статистика
- Возможность задавать порядок вопросов и вариантов ответов, должна быта возможность ввода  собственного ответа пользователя
- View или api-view, которая возвращает следующий вопрос для пользователя (с учетом прогресса)
- PostgreSQL (код должен быть готов к работе с ним)

По желанию (будет плюсом):
- Фронтенд (Django Templates или React)
- Тесты
- Docker / конфигурационный файл docker-compose
- ASGI / оптимизации под нагрузку (в комментариях)

Не нужно:
- Поднимать внешние сервисы и БД
- Присылать работающий продакшн-стенд
-Реализовывать полную систему авторизации (достаточно идентификации пользователя)







## Проработанное:


### Функции:
1. Создать опрос
2. завести вопросы/ответы в него
3. получить статистику по опросу
4. получить список своих опросов
5. пройти опрос (получить следующий вопрос, ответить). Повторное прохождение запрещено: один пользователь — одно прохождение опроса
6. редактирования опроса (после публикации запрещено) (изменения порядка вопросов и вариантов, публикации и закрытия опроса)
7. клон опроса
8. список доступных для прохождения опросов

777. Нагрузочное тестирование сервиса: 1.000.000 рандомных прохождений опросов для получения и теста статистики и системы (вне ТЗ)

#### Какую статистику получаем:
количество ответов
популярные ответы
среднее время прохождения
время на каждый вопрос, над каким дольше всего думали


### Требования:
#### Требования по нагрузке
Опросов: ~1 000 000
Вопросов в каждом опросе: ~15
Вариантов ответов на каждый вопрос: ~5
Пользователей: ~15 000 000
Каждый пользователь проходит в среднем 5 опросов
